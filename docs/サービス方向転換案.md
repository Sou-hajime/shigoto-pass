# シゴトパス サービス方向転換案

## 新しい定義

シゴトパスは「福祉施設を検索するサイト」ではなく、企業の仕事を受け付け、実行可能な工程へ分解し、適切な実行拠点へ流して、納品までをまとめるBPO受注基盤を目指す。

企業への約束は「施設を紹介する」ではなく、**外注したい仕事を、相談から納品まで一本化する**こと。実行拠点への約束は、**営業をしなくても、能力と空きに合う工程だけが届く**こととする。

## 福祉との距離感

福祉を隠す必要はないが、企業向けの入口にはしない。

- 最初に伝える：業務範囲、数量、期限、品質、セキュリティ、管理負担の軽減
- 見積前に伝える：複数の実行拠点で分担する可能性、運営者の管理範囲、情報の共有範囲
- 信頼形成として伝える：就労支援事業所を含む実行ネットワークと、仕事を通じて生まれる社会的価値

「福祉だから発注する」だけに依存せず、「業務委託先として成立し、その結果として社会的価値も生む」という順序にする。

## 画面の方向転換

### 企業向けトップ

主メッセージ：

> 人手が足りない仕事、相談から納品までまとめてお任せください。

主導線：

1. 仕事を自由文で相談
2. 追加質問へ回答
3. 整理された案件仕様を確認
4. 概算・実行方法の回答を受ける

施設一覧は主画面から外し、「どの施設に頼むか」ではなく「どの体制で完了させるか」を運営者が提案する。

### 実行拠点向け

中心機能を掲載プロフィールから次へ変更する。

1. 能力・設備・品質・制約を登録
2. 現在の受入可能量を更新
3. 適合する工程の打診を受ける
4. 数量・開始日・条件を確認して回答
5. 進捗と納品物を報告

### 運営向け

MVPで最も重要な画面とする。

1. 業務相談の受付
2. 案件仕様の編集・確定
3. リスク確認
4. 実行拠点候補の抽出
5. 工程・数量の分配
6. 打診と回答管理
7. 進捗・検品・納品管理

## MVPで検証する一連の動き

最初に検証するのは検索数や施設登録数ではなく、次の一連の運用が成立するかである。

1. 企業から曖昧な業務相談を1件受ける
2. 人間がAI補助を使って案件仕様へ整える
3. 2〜3拠点へ工程または数量を分けて打診する
4. 運営者が進捗を集約する
5. 共通基準で検品する
6. 企業へ一括納品する
7. 原価、調整時間、不良率、納期遵守、粗利を記録する

## 初期対象

工程と合格基準を標準化しやすい業務から始める。

- データ入力・転記
- スキャン・PDF化
- EC商品情報登録
- 封入・ラベル貼り・梱包

AI教師データ、SNS運用、清掃、発送代行は、品質や権限、現地性、物流責任が異なるため同時に広げない。

## 公開デモの変更優先順位

1. TOPの主語を「対応施設を探す」から「仕事を相談する」へ変更
2. 検索結果を施設ランキングではなく、整理された案件仕様と想定実行体制へ変更
3. 企業向けに一括窓口、案件分割、検品、一括納品を説明
4. 施設向けに能力登録と案件打診の流れを説明
5. 運営管理デモとして案件仕様、候補拠点、割当、進捗を追加

## 次に決める必要があること

画面実装へ進む前に、以下は事業判断として確定が必要になる。

- 運営者が企業との契約上の受託者になるか
- 実行拠点との関係を再委託とするか、紹介・取次とするか
- 検品と瑕疵対応をどこまで運営者が負うか
- 企業への見積方法と実行拠点への支払方法
- 初期地域、初期案件カテゴリ、最初に参加する実行拠点数

この5点が決まるまでは、公開画面で「品質保証」「丸投げ可能」「一括受託」を確定表現にしない。
