# 施設検索型ではなく運営介在型BPOを中核にする

シゴトパスは、企業が福祉施設を検索して直接発注するマーケットプレイスではなく、企業の業務相談を運営者が案件仕様へ整え、工程分解、複数拠点への配分、進捗管理、検品および一括納品までを担う運営介在型BPOとして設計する。企業の本来の目的は施設探しではなく仕事の完了であり、施設側にも営業・契約・顧客管理を個別に負わせないためである。

## Considered Options

- 施設検索・直接連絡型：立ち上げは軽いが、企業へ品質・納期・契約管理を戻してしまうため採用しない。
- 案件掲載・施設応募型：需給発見には使えるが、大型案件の分散、統一品質、一括責任を実現できないため中核にはしない。
- 運営介在型BPO：運営コストと受託責任は増えるが、発注者と実行拠点の双方に提供したい価値と一致するため採用候補とする。

## Consequences

- 企業向け画面の中心を「施設を探す」から「仕事を相談し、仕様と進捗を確認する」へ変更する。
- 施設向け画面はプロフィール掲載ではなく、能力登録、案件打診、受注可否、進捗・納品の管理を中心にする。
- 施設名や福祉性を隠すのではなく、企業の課題解決を先に示し、実行体制と社会的価値は透明性を保って説明する。
- 正式採用前に、契約主体、再委託構造、検品責任、瑕疵対応、個人情報、事故時責任、保険および資金繰りを確定する。
