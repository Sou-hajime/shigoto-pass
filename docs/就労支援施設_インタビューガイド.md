# 「シゴトつなぐ」就労支援施設向けインタビューガイド

## 1. 調査の目的

企業が依頼したい仕事から就労支援施設を探し、対応工程・数量・納期・品質・料金などを比較して相談できる業務マッチングサービス「シゴトつなぐ」について、次を明らかにする。

- 施設が仕事の獲得・受注・遂行で本当に困っていること
- 管理者と現場職員で異なるニーズ、懸念、導入条件
- サービスを使いたい場面と、使わない理由
- 必須機能と、あると便利な機能
- 掲載・問い合わせ対応・案件管理に許容できる負荷
- 導入決裁者、予算、支払意思、受け入れやすい料金体系
- 初期顧客に適した施設像と、提供価値の優先順位

この調査では「欲しい機能」を直接集めるだけでなく、過去に実際に起きた出来事、現在の代替手段、困りごとの頻度と大きさを確認する。

## 2. 対象者と推奨人数

### 管理者・経営側：6〜8名

- 法人代表、施設長、管理者、サービス管理責任者
- 仕事の受注や外部連携、予算・契約の判断に関わる人
- A型、B型、就労移行支援、生活介護などを偏らせずに含める
- 都市部／地方、単独拠点／多拠点、仕事が充足／不足の双方を含める

### 現場職員側：6〜8名

- 職業指導員、生活支援員、就労支援員、営業担当、案件管理担当
- 企業案件の見積、作業分解、利用者への割り振り、検品、納品のいずれかを担当する人

可能なら同一施設の管理者と職員を**別々に**聞く。上下関係による遠慮を防ぎ、認識差も比較できる。

## 3. 実施概要

- 形式：1対1の半構造化インタビュー
- 時間：60分（価格検証を厚くする場合は75分）
- 記録：同意を得たうえで録音。個人名・利用者名・企業秘密は記録しない
- 謝礼：地域・職位・所要時間に応じて設定
- 用意するもの：現行デモ、画面共有、回答記録シート

### 60分の時間配分

| 時間 | 内容 | 狙い |
|---|---|---|
| 0〜5分 | 導入・属性確認 | 安心して本音を話せる状態をつくる |
| 5〜20分 | 現状と直近の実例 | 課題を事実ベースで把握する |
| 20〜30分 | 困りごと・優先順位 | 課題の頻度・深刻度・代替手段を測る |
| 30〜45分 | コンセプト・デモ評価 | 利用意向、必須情報、導入障壁を確認する |
| 45〜55分 | 料金・契約 | 支払意思と受け入れやすい課金方法を確認する |
| 55〜60分 | 総括 | 最重要点と紹介候補を回収する |

## 4. 冒頭の読み上げ文

> 本日はありがとうございます。私たちは、企業が依頼したい仕事から、対応できる就労支援施設を探して比較・相談できるサービスを検討しています。今日はサービスを褒めていただく場ではなく、現場に合わない点や使わない理由も含めて率直に伺いたいです。正解・不正解はありません。まず現在の仕事の獲得や運用について伺い、その後に画面をご覧いただきます。お話は改善目的にのみ利用し、施設名や個人が特定される形では扱いません。

録音する場合は、ここで明示的に同意を得る。

## 5. 共通質問：属性と現在地（5分）

1. 現在の役割と、企業から仕事を受ける際の関わり方を教えてください。
   - どこからどこまで担当するか
   - 最終的な受注判断をする人は誰か
2. 施設の種別、利用者数、職員数、主な作業を差し支えない範囲で教えてください。
3. 企業案件は、売上づくり・工賃向上・訓練・地域連携の中でどのような位置づけですか。
4. 現在、仕事量は「足りない・ちょうどよい・多すぎる」のどれに近いですか。季節による違いはありますか。

## 6. 共通質問：仕事獲得の実態（10分）

「普段はどうしていますか」だけで終わらせず、**直近の具体例**を聞く。

1. 直近で新しい企業の仕事を獲得したときの経緯を、最初から教えてください。
   - きっかけ：紹介、営業、行政、既存企業、Web、共同受注窓口など
   - 初回接触から受注までの期間とやり取りの回数
   - 誰が何を確認し、どこで受注を決めたか
2. 新規案件を探すために、誰が月に何時間くらい使っていますか。
3. 継続案件と単発案件の割合、望ましい割合はどの程度ですか。
4. これまで断った案件の直近例を教えてください。何が理由でしたか。
   - 数量、納期、単価、工程、品質、設備、場所、配送、利用者との相性、職員負荷、契約・責任
5. 受注後に「想定と違った」となった案件はありますか。何を事前に確認できれば防げましたか。
6. 仕事が足りない時、現在はどう補っていますか。その方法の良い点・不満な点は何ですか。

## 7. 共通質問：受注から納品までの実態（10分）

1. 問い合わせを受けてから納品するまでの流れを、順番に教えてください。
2. 受注可否を判断するために、企業から最低限必要な情報は何ですか。
   - 作業内容と工程
   - 数量、ロット、頻度
   - 納期、開始時期
   - 単価、予算、見積条件
   - 資材、保管、受渡し、配送費
   - 検品基準、不良時の対応、損害責任
   - 個人情報、機密、食品、危険物など
3. 見積、作業の分解、利用者への割り振り、進捗管理、検品、請求は、それぞれ誰がどの道具で行いますか。
4. 最も手間がかかる工程は何ですか。1案件あたりどのくらい時間がかかりますか。
5. ミスや納期遅延が起きそうな時、どのように把握し、企業へ連絡しますか。
6. 複数施設で分担した経験はありますか。ある場合、何が難しかったですか。

## 8. 管理者向け質問（10分）

1. 今年、企業案件について改善したい経営課題は何ですか。
2. 良い案件とはどのような案件ですか。逆に、売上があっても避けたい案件は何ですか。
3. 案件を増やすうえで一番の制約は何ですか。
   - 営業力、職員数、利用者の特性、設備、スペース、送迎・配送、品質保証、原価把握など
4. 工賃・売上・稼働率・継続率など、案件獲得の成果を何で判断していますか。
5. 外部サービス導入時に確認することは何ですか。
   - 費用対効果、個人情報、契約、事故責任、サポート、操作性、既存システムとの重複
6. 導入には誰の承認が必要ですか。予算はどの費目から出ますか。検討時期はいつですか。
7. 施設情報や実績、参考単価、空き状況を公開することへの懸念はありますか。どこまでなら公開できますか。
8. 企業から直接連絡が来る方式と、事務局が間に入る方式のどちらが安心ですか。なぜですか。

## 9. 現場職員向け質問（10分）

1. 企業案件に関する1週間の業務で、時間を取られていることは何ですか。
2. 案件の説明を受けた時、利用者が対応できるかをどのように判断しますか。
3. 作業手順書や見本、注意点はどのように作成・共有していますか。
4. 急な欠席、体調変化、得意不得意がある中で、数量と納期をどう見立てますか。
5. 営業担当や管理者と現場の間で、情報不足や認識違いが起きることはありますか。
6. 企業とのやり取りで負担・緊張を感じることは何ですか。
7. 新しい案件が増えると、どの業務が先に限界になりますか。
8. サービスへの登録や更新を担当するとしたら、どの頻度・所要時間なら続けられますか。

## 10. コンセプト提示

現状の話を十分聞いた後、次の説明だけを行う。最初から機能を詳しく説明しすぎない。

> 「シゴトつなぐ」は、企業が梱包、発送、データ入力、清掃などの依頼内容・数量・納期を入力し、対応できる就労支援施設を探して比較・相談できるサービスです。施設は、得意な仕事、対応工程、数量、納期、受渡し方法、品質管理、対応できない条件、実績などを登録します。

説明後、まず沈黙して第一声を取る。

1. 今の説明を聞いて、最初にどう思いましたか。
2. ご自身の言葉では、どのようなサービスに見えましたか。
3. 現在のどの仕事を置き換えたり、楽にしたりしそうですか。何も変わらない点はどこですか。
4. 直近6か月で、このサービスがあれば役立った具体的な場面はありますか。
5. 逆に、使わないとすれば一番大きな理由は何ですか。

## 11. デモを使った観察（10〜15分）

「良いですか」と聞く前に、説明なしで操作してもらう。回答者には声に出して考えてもらう。

### タスク1：施設として掲載を検討する

> あなたの施設がこのサービスへの掲載を検討しているとします。何が掲載されるか、登録相談まで進んでみてください。

観察する点：入口を見つけられるか、必要情報を理解できるか、登録負荷をどう感じるか。

### タスク2：企業から来た案件を判断する

> 「商品500個を袋詰めし、ラベルを貼って月末までに納品」という相談が届いたとします。対応できるか判断するために画面を確認してください。

観察する点：どの情報を先に見るか、不足情報は何か、誰に確認するか。

### 操作後の質問

1. 期待どおりだった点と、分かりにくかった点を教えてください。
2. 掲載する前に確認したいことは何ですか。
3. 案件通知に必ず載せてほしい情報は何ですか。
4. 施設情報のうち、毎回更新できるもの／更新が難しいものは何ですか。
5. 「空き状況」「参考単価」「対応可能数量」は、どの粒度・頻度なら正確に出せますか。
6. 問い合わせが増えたとき、どんな絞り込みや事前審査が必要ですか。
7. 企業との間に事務局が入ってほしい場面はどこですか。
8. この画面を、管理者以外の職員も使えそうですか。権限分けは必要ですか。

## 12. 機能ニーズの確認（5〜10分）

最初は自由回答で聞き、その後に候補を提示する。

1. このサービスに一つだけ機能を追加できるなら、何を選びますか。なぜですか。
2. 次の候補を「必須」「あると便利」「不要」「むしろ困る」に分けてください。

| 機能候補 | 深掘りする観点 |
|---|---|
| 案件の自動マッチング・通知 | 通知条件、頻度、見逃し防止 |
| 受注可否の簡単回答 | 保留、辞退理由、回答期限 |
| 見積書・請求書作成 | 現行様式、会計連携 |
| 作業工程・原価・単価の計算補助 | 誰が使うか、精度への期待 |
| 案件・納期・進捗管理 | 現場入力の負荷、スマホ利用 |
| 作業手順書・検品表のテンプレート | 写真、動画、やさしい日本語 |
| 企業とのチャット・ファイル共有 | 記録、既読、電話との使い分け |
| 契約・秘密保持・個人情報対応 | ひな型、電子契約、責任分界 |
| 配送・集荷の手配 | 対応地域、費用負担 |
| 複数施設での共同受注 | 幹事施設、分配、品質統一 |
| 企業・施設の評価、実績表示 | 公開範囲、不当評価への懸念 |
| 空き状況のカレンダー | 更新担当、更新頻度 |
| 事務局による案件整理・交渉代行 | 有料でも必要か、介入範囲 |
| 電話・FAXでの代理登録 | デジタル操作が難しい施設への必要性 |
| 職員ごとの権限・承認フロー | 管理者、営業、現場の役割分担 |

3. 上位3つを選び、それぞれ「ないと使わない理由」を教えてください。
4. 一見便利でも、運用負荷が増えそうな機能はどれですか。

## 13. 利用意向と導入条件（5分）

1. 現時点での利用意向を0〜10点で表すと何点ですか。
2. なぜその点数ですか。
3. 1点上がるために必要なことは何ですか。0〜3点なら、利用を阻む決定的な理由は何ですか。
4. 無料トライアルがある場合、実際に試すために必要な準備は何ですか。
5. 最初の30日でどんな成果が出れば継続しますか。
6. どの種類・単価・頻度の案件が月に何件届けば価値を感じますか。
7. 逆に、どのような案件ばかり届くと利用をやめますか。

## 14. 価格・支払意思の聞き方（10分）

価格は、機能説明直後に「いくら払えますか」とだけ聞かない。現在のコスト、得られる価値、課金主体を先に確認する。

### A. 現在のコストと価値

1. 新規企業を1社獲得するために、職員時間・交通費・広告費などをどのくらい使っていますか。
2. 案件獲得や管理のために、現在お金を払っているサービス・団体・営業代行はありますか。月額や手数料はいくらですか。
3. 継続案件が1件増えると、施設にとって月にどの程度の売上・工賃・稼働の価値がありますか。
4. 費用を払うなら、どの成果に対して払うのが納得しやすいですか。

### B. 料金体系

次を「最も納得」「条件付きで可」「不可」に分類し、理由を聞く。

- 掲載無料＋成約時に受注額の一定割合
- 掲載無料＋案件1件ごとの固定手数料
- 月額固定で問い合わせ・成約は無料
- 基本無料＋便利機能のみ月額
- 企業側のみ有料で施設は無料
- 初期登録・取材代行のみ有料

確認事項：誰が払うべきか、成約の定義、継続案件の手数料期間、返金条件、予算化のしやすさ。

### C. 月額価格の4問

月額プランを想定できる回答者に、機能範囲を固定して次を聞く。

1. 月額いくらを超えると「高すぎて利用できない」と感じますか。
2. 月額いくらを超えると「高いが、成果次第では検討できる」と感じますか。
3. 月額いくらなら「妥当で利用しやすい」と感じますか。
4. 月額いくらを下回ると「安すぎて、案件やサポートの品質が不安」と感じますか。

各回答の後に「その金額の根拠」「含まれていると想定した機能」「必要な案件数・売上」を必ず聞く。

### D. 具体価格による最終確認

インタビューごとに提示額を変えず、事前に決めた3水準を順番ではなく回答者ごとに入れ替えて聞く。

> 仮に、条件に合う案件通知、施設ページ、企業との相談、事務局サポートが含まれ、月額○円だとしたら、実際に契約を検討しますか。「契約する」「条件付きで検討」「契約しない」のどれですか。

続けて、必要な無料期間、解約条件、稟議資料、成果保証の要否を聞く。これは営業の約束ではなく、価格仮説の検証だと伝える。

## 15. 終了時の質問（5分）

1. 今日の話の中で、私たちが最も重く受け止めるべきことは何ですか。
2. このサービスを一言で説明するとしたら、どのように説明しますか。
3. 私たちがまだ聞いていない重要なことはありますか。
4. 次回、改善版を10〜15分触って意見をいただけますか。
5. 同じ課題を持ちそうな管理者または職員を紹介いただくことは可能ですか。

## 16. インタビュアーが避けること

- 「便利ですよね」「使いたいですよね」と同意を誘導する
- 将来の仮定だけを聞き、過去の実例を確認しない
- 回答者のアイデアを、そのまま必要機能と決める
- デモを先に長く説明して、現状の課題を聞き漏らす
- 「無料なら使う」を需要の証拠とみなす
- 価格だけを聞き、必要な成果や予算の出どころを確認しない
- 沈黙を埋めるために選択肢を早く提示する
- 施設への営業やサービスの正当化を始める

有効な深掘りは「直近ではいつですか」「具体的には何が起きましたか」「誰が担当しましたか」「どのくらい時間・金額がかかりましたか」「なぜそうしたのですか」である。

## 18. インタビュー後の分析方法

各発言を機能別ではなく、まず次の流れに沿って整理する。

`仕事を探す → 問い合わせを受ける → 受注可否を判断する → 見積・契約 → 作業設計・割当 → 進捗・品質管理 → 納品・請求 → 継続受注`

各段階について、以下を1行ずつ記録する。

- 誰が行うか
- 困りごとの具体例
- 頻度
- 時間・金額・機会損失
- 現在の対処法
- 対処法への不満
- サービスで解決できる可能性
- 解決に必要な条件・リスク

### 優先度の付け方

課題ごとに以下を5点満点で評価する。

- 発生頻度
- 深刻度
- 現在の代替手段への不満
- 対象施設の多さ
- サービスとの適合度
- 支払意思または導入意思

発言数だけで優先順位を決めず、具体的な過去行動や、すでに時間・費用を使って対処している事実を強い証拠として扱う。

### 管理者と職員で分けて比較する項目

- 認識している最重要課題
- 案件を増やしたい度合い
- 許容できる案件条件
- 登録・更新負荷
- 必須機能
- リスク認識
- 利用意向

管理者は売上や工賃を重視していても、職員側では作業設計・検品・連絡負荷が導入障壁になる可能性がある。両者の回答が一致する機能と、衝突する機能を分けて扱う。

## 19. 最初の検証で判断したい基準

以下は仮の判定基準。実施前にチームで数値を確定する。

- 対象者の半数以上が、直近6か月の具体的な困りごとを説明できる
- 3分の1以上が、現在その解決に費用または月2時間以上を使っている
- 半数以上が、具体的な利用場面を一つ以上説明できる
- 半数以上が、デモ確認後の利用意向を7点以上とする
- 無料トライアルだけでなく、登録作業や次回検証に協力する意思が複数得られる
- 有料化する場合の課金主体、料金体系、成立に必要な案件価値が説明できる

この基準を満たさない場合も、単純に機能を増やさず、「対象施設が違う」「仕事獲得ではなく受注後の運用が課題」「施設課金では成立しにくい」など、前提そのものを見直す。
